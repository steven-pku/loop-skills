# BATNA Gate Guide

> Gate 先于一切写卡动作。没有替代方案就没有谈判筹码；没有底线就没有「谈崩」的判定标准——两者缺一，写出来的话术只是台词背诵。
> BATNA 概念出处：Fisher & Ury《Getting to Yes》（1981）；底线（reservation point）理论根：Raiffa（1982）。详见 evidence-notes.md。

## 双问

1. **这场谈话谈崩了，你接下来具体做什么？**
   合格答案是可执行动作，不是情绪表态：「接受手上另一个 offer（base 低 15% 但通勤近）」「回到现岗，其实项目和老板都还行，再看半年」「继续面试，手上有两个二面在走」。
2. **你的硬底线是什么——低于什么条件你宁可走？**
   合格答案是可判定条件 + 触线动作：「base 低于 X 就转谈签字费，签字费也没有就婉拒」。「再看吧」「到时候感觉一下」不算底线。

任一答不出 → 走下方构建路径，**不写卡**。双问都过 → 把答案压成一句「筹码陈述」记入 Brief（例：「我有 A 公司 offer 托底 + 现岗可留，底线 X，低于即转议题或走」），后续每张卡都不得与它矛盾。

**复合底线检查**：金额以外、会改变接受或退出决定的必要条件也须可判定。若已识别“review 的最低可接受内容尚未定义”等缺口，Gate 仍未通过；先确认用户自己的最低条件，不代替用户选择“只评估即可”或要求保证涨薪。此时不生成报价卡、让步阶梯或启动 mock；用户拒绝澄清时仅给下方低风险地板。对方是否批准、实施细节尚待协商，不等于用户底线未知；最低条件与触线动作已明确时可正常准备，不要求谈判前取得批准。

## BATNA 构建路径（fast iteration，不进全环）

### 路径 A · 跳槽期（offer 谈薪 / 跳槽反向要价）

按强度排序盘点，取最强项作 BATNA：

1. 手上已有的其他 offer（最硬——数字、deadline、真实意愿逐项确认）
2. 在走的面试 pipeline（几个、到什么轮次、大概概率——只算得上「半个 BATNA」，卡面表述时不得夸大为已有 offer）
3. 现岗保留（不是耻辱选项：现岗的真实收益 / 成本列一遍，很多人盘完发现「留下」是完全可执行的 Plan B）
4. 以上全无 → 先构建并确认其他可执行的 Plan B，例如明确下一步求职安排及可承受的空窗范围。未确认前仅做 Gate 构建；用户拒绝补充时遵守下方低风险地板，不自动进入完整卡组。只有已确认弱而真实的替代方案，才适用「弱 BATNA 校准」。

### 路径 B · 在职（提加薪 / 拒绝安排 / 提离职）

「留在现岗但不加薪」本身就是默认状态，所以在职场景的 BATNA 问的是**另一个方向**：

1. 外部市场热度：最近 6 个月有没有猎头触达 / 同岗位跳槽案例？没有数据就标〔待核〕，别拿感觉当筹码。
2. 内部替代：转岗 / 换项目 / 调整职责范围，哪些是真实可选项？
3. 「维持现状」的真实成本：继续不谈的代价（薪资倒挂、心气流失）列出来——它决定这场谈话值不值得冒关系风险。

### 幻想 BATNA 探底

「大不了裸辞」「此处不留爷自有留爷处」→ 先核可执行性：可承受的空窗范围、已知求职进展、实际下一步。不索取存款余额或原始流水，未知招聘周期不编造。不能说明可执行方案就保留未知，先构建 BATNA；不把未经证明的方案写成已有筹码，也不因缺资料断定用户撒谎。

## 弱 BATNA 校准

弱而真实的 BATNA（「现岗还过得去」）**过闸**——Gate 挡的是「无」和「假」，不挡「弱」。但降档处理：

- 语气档位调至协作框架（见 SKILL.md Polish 节）：多用交换与未来机制（调薪 review / 半年后重谈），少用当下摊牌。
- 锚定卡幅度收敛：**有可信市场数据**时理想层贴近数据中位而非高位；**无可信数据**时不得虚构「市场中位」当锚——改走后报探底、争取时间补数据，或把重心转向低风险议题（调薪机制 / 试用期后 review / 签字费）。
- 阶梯加一层「体面收场」台阶：谈不动时如何不伤关系地收（「今天先到这，我消化一下」），避免弱筹码硬顶到僵。

## 底线发现法（Q2 答不出时用）

BATNA 有构建路径，底线也有——用**二分迭代**帮用户把「说不清」变成数字：「对方最终给到 X，你是松一口气还是遗憾？」遗憾 → 试探更高一档；松口气 → 试探更低一档；两三轮收敛到「低于它明显该走、高于它明显该留」的临界带，再补触线动作（转议题 / 体面收场 / 走）。副产品：迭代过程会自然暴露用户真正在乎的非 base 议题（「28 给到但要 996 我还是遗憾」→ 工时进可交换清单）。

## 用户拒绝过闸

「别问了，直接给我一套话术」→ 说明一次边界，仅给开场、信息收集问题、暂停／退出句，标「未经 BATNA 校准，非完整卡组」，附两项未答 Gate 问题。不得给数字锚、让步阶梯、摊牌或完整卡组；通用模板不能覆盖这条地板。用户说接受风险也不能让未知 Gate 自动通过。弱而真实的 BATNA 仍按上节正常过闸。
