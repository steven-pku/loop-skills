# Script Card Patterns（谈判话术卡）

> 卡是带进现场的工具，不是一篇稿：每张卡 ≤ 半屏、可扫读、只引用 Brief 事实。Gate 已过的完整候选按场景选开场、报价、异议与收尾；拒答 Gate 仅开场、信息问题、暂停／退出，并标非完整卡组，不含数字锚或阶梯。模板见 `assets/script-card-template.md`。

## 通用措辞纪律（中文职场语域）

- **坚定而不对抗**：立场硬、措辞软。「我理解 X，同时我的情况是 Y」优于「你们这不合理」。
- **禁翻译腔**：不用「让我们达成双赢」「我方认为」类教科书句；说人话（「这事我想跟你商量个两边都行的办法」）。
- **禁指控式反问连用**：「你们不觉得…吗？」「难道…？」连续出现 = 语气维扣分。
- **转发存活测试**：每句话假设会被截图转给对方老板 / HRD 看——仍然站得住 = 合格。
- **不撒谎，会转向**：任何不想答的问题（当前薪资 / 还面了哪家）都有转向句，转向 ≠ 虚构。

## 开场卡

功能：用简短开场完成关系锚定 + 谈话框架，让对方知道「这是一场准备过的正式谈话」而不是抱怨或试探。

```text
结构：感谢/关系句（1 句）→ 谈话目的直陈（1 句）→ 框架预告（1 句）
例（在职加薪）：「谢谢你抽时间。今天想正式聊一下我的薪酬——过去一年我的职责和产出变化比较大，
我整理了具体情况，想听听你的看法，也想了解今年调薪的空间和机制。」
```

要点：目的直陈不绕弯；框架预告给对方安全感（他知道这场谈话的边界）。

## 锚定卡

功能：表达真实个人目标或有据诉求，按 Brief 的先报／后报／反锚分支执行。以下金额、市场依据与 review 时点都是合成措辞示意；实际必须替换为用户明确的目标和可用事实。Gate 地板不得使用本节。

```text
先报分支：精确数 + 依据陈述 + 开放句
例：「结合我看到的同岗位数据和我现在的整体 package，我的期望是 26.5K——
这个数字是怎么算的我可以展开。当然我也想听听你们的结构。」

后报分支：缓冲反问句（先探对方范围）
例：「薪资我肯定关心，不过它取决于整体 package——职级、奖金结构这些。
方便先介绍下这个岗位的范围和结构吗？」

反锚分支（对方已报价）：拆口径 + 精确数反锚 + 依据
例：「谢谢，我先确认下口径：24K 里 base 是多少、浮动怎么算？——了解了。
坦白说这个数和我的预期有差距：结合同岗位数据和我现在的 package，
我的期望是 26.5K base。差距怎么补，我们可以一起看看签字费或定级的空间。」
```

要点：点价或范围须能解释；整数也可成立，不为了精度造数。研究不支持固定人民币步长，见 brief-guide.md。给对方回应空间，不把某句措辞当普遍成败规律。

## 异议应对卡（每张一招）

```text
格式：
【对方说】原话预判
【你答】应对台词（回应 + 转向，2-3 句内）
【逻辑】一句话：这么答在打什么（给自己看的，现场不说）

例——招数：画饼
【对方说】「先按这个数进来，以后表现好有的是机会。」
【你答】「我相信机会是有的——那我们把它落实一点：如果 base 现在动不了，
能不能在 offer 里写一个入职 6 个月的调薪 review，标准我们现在就对齐？」
【逻辑】把口头未来换成书面机制；未能确认的未来条件仍有不确定性，不据此断言对方欺骗。
```

要点：应对必须有转向路径（转议题 / 转机制 / 转时间），只会「我理解但我坚持」的卡是空转；每张卡的逻辑句必须能回溯到 Brief（对方视角表或阶梯）。

## 收尾卡

功能：明确记录与核对谈到的事项；记录不等于法律效果得到保证。

```text
结构：复述确认 → 落字清单 → 下一步与时间点
例：「我确认一下今天谈的：base X，签字费 Y，6 个月调薪 review 标准是 Z——
这些会都写进 offer 吧？那我等你们的正式文件，大概什么时候能发？」
```

落字清单参照 cn-workplace-notes.md「offer 细节确认清单」；口头承诺不入 offer 的项，收尾卡显式追一句。

## 场景变体

拒绝 / 婉拒 / 提离职 / 坏消息场景的卡组骨架差异（缓冲结构、去锚定卡等）见 scenario-guide.md 各场景节——卡型不变，组合与语气档变。
