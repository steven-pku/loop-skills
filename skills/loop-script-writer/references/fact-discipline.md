# Fact Discipline — F0-F3（口播变体）

口播脚本的事实会被念给成千上万陌生人听，且无法像图文一样贴出处链接——标签纪律因此更严，不是更松。

| 级 | 定义 | 口播处理规则 |
|---|---|---|
| **F0** | 观点 / 立场 / 体验（「我觉得这个功能被低估了」） | 自由表达；口播的人格魅力就在这里，不要把观点稀释成免责声明 |
| **F1** | 用户提供的事实（自己的数据、亲历） | 照用；口播中自然带上来源（「我自己测了一周」） |
| **F2** | 可核公开事实（价格、功能、日期、事件） | 载重的必须核实或标〔待核〕交回用户；口播念稿前 F2 必须清零——念出去就收不回 |
| **F3** | 高风险载重断言（健康/法律/金钱收益/具体统计数字） | 必须有真实来源且在口播中说得出来源（「XX 官方文档写的」）；给不出 = 删改内容绕开，**unsourced F3 = fatal** |

## 口播特有规则

- **数字诱惑**：钩子类型 6（权威/数字背书）依赖数字压场，最容易诱发编造。规则：钩子里的每个数字按 F 级处理，无源数字宁可换钩子类型。
- **「大概」不是豁免**：「大概能省一半时间」若为载重承诺（类型 3 利益钩子），按 F2 处理。只有用户明确提供了自己的真实测量或亲历，才可以用第一人称经验表述并标 F1；否则去掉数字，改成无事实负担的建议，不得虚构「我自己……」的经历。
- **平台数据红线**：本 skill 自身的引用纪律同样适用于产出——脚本里不得出现「官方规定完播率 X% 才推流」这类查无出处的平台机制断言（参见 `hook-types.md` 禁引数字清单）。
- **改编场景**（文章改口播 / 时长压缩）：原文的事实标签不继承信任——原文说「研究表明」而无出处，改编时按 F2 悬置，不因「原文这么写」放行。
- **原文完整性**：只有摘要、大纲、占位符或无法读取的附件时，不得凭它们扩写成「原稿」。文章改口播或时长压缩必须先取得完整原文；拿不到就说明缺口并停在索要原文。

- **候选稿同门**：无源健康／法律／收益统计不得进入任何可选口播开头或备选稿，即使以反问、反驳或辟谣包装也不复述该数字作钩子。可以在稿外诊断中引用并说明待核；所有候选与最终稿均须删掉无源高风险数字。

## 整稿检查与交付状态

检查每一条载重主张，不限于数字或开头。对具体观众行为的确定归因、唯一有效办法、必然收益及零损失保证，按实际内容判 F2／F3；加“我觉得”不能把可核事实变成 F0。没有资料时改成有条件的练习建议，不虚构原因。

事实待核可以出现在稿外诊断清单；未解决的载重 F2 不得进入标为可念稿的口播列。用户愿意承担风险不等于核实事实。交付可念稿前，应核实、删除或改写掉事实依赖；保留正常观点和明确假设，不为追求安全而拒绝合法写作。
