# JD 解析与映射矩阵

## JD 解析四件套

1. **硬需求**：学历/年限/必备技能/证照——JD 用「必须/要求/须具备」标注的项。
2. **软偏好**：「优先/加分/熟悉者佳」项。
3. **关键词集**：技能、工具、领域术语——**按 JD 原词记录**（原词是搜索与初筛的对齐锚点，「数据分析」≠「用户增长分析」）。
4. **层级信号**：带人/独立负责/参与执行的措辞差异；汇报线；「资深/高级/专家」称谓。

JD 缺失时沿用 SKILL.md 的 Gate 分支：尚无清晰目标，先建立岗位画像并补真实 JD 样本；已有岗位名与已知职责、按粗画像通过 Gate 的，标“JD 正文缺失，按岗位画像粗匹配”，只映射已知要求，不另设“必须补 1 份 JD”门槛，也不从薪资或岗位名编造硬需求。

## 映射矩阵格式

```markdown
| JD 需求 | 类型 | 账本证据 | 覆盖度 |
|---|---|---|---|
| 3 年+ 用户增长经验 | 硬 | E01（2 年）+ E03（1.5 年相邻域） | ⚠️ 部分（跨域拼接，如实呈现） |
| 精通 SQL | 硬 | E02 个人动作及产出记录（日常取数＋报表搭建） | ✅ |
| 带过 5 人以上团队 | 软 | 无 | ❌ 进无法覆盖表 |
```

## 无法覆盖表（必须显式）

- 每条硬需求：要么有账本证据，要么进「无法覆盖」表——**没有第三种（硬凑/模糊化）**。
- 呈给用户三选一：① 补充未入账本的真实经历 ② 接受差距（简历如实呈现，面试准备应对话术）③ 判断该 JD 匹配度过低，换目标。
- 部分覆盖如实标注（「2 年经验 vs 要求 3 年」），由用户决定是否投递，不由 skill 粉饰。

## 排序原则

Draft 按映射矩阵的覆盖强度排信息权重：强覆盖的经历前置展开，弱相关压缩，无关裁剪。不按原简历顺序惯性排列。
