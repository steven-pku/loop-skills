# Article Patterns

Use this reference when choosing article structure.

## Pattern 1: Target -> Argument -> Objection -> Turn -> Judgment

Best for Chinese opinion essays.

Structure:

```text
1. Hook: concrete pain, contradiction, or counterintuitive observation
2. Target: name the wrong belief or behavior
3. Core stance: one sentence the reader can repeat and refute
4. Argument: case, observation, data, or worked example
5. Objection: strongest reasonable counterargument
6. Turn: why the stance still holds, or where its boundary is
7. Judgment: final position, self-check, or action
```

Use when the user asks for 观点文章, 行业观察, thought leadership, public-account essays, or social-media longform with a position.

## Pattern 2: Problem -> Diagnosis -> Template -> Case -> Judgment

Best for practical method articles.

Structure:

```text
1. Hook: most people are doing X wrong
2. Problem: why X fails
3. Diagnosis: the real issue is Y
4. Template: use this structure instead
5. Case: show the template in action
6. Mistakes: what breaks the method
7. Judgment: how to know it works
```

Use when the user asks for a how-to article, workflow explanation, practical guide, or beginner-friendly method.

## Pattern 3: Observation -> Contradiction -> Explanation -> Implication

Best for thought-leadership articles where the stance emerges from a trend.

Structure:

```text
1. Observation: something happening in the field
2. Contradiction: why it is misunderstood
3. Explanation: what is really changing
4. Example: one concrete case
5. Implication: what readers should do differently
6. Judgment: what this means next
```

Use when the user asks for trend judgment, industry observation, or personal insight.

## Pattern 4: Before -> After -> Mechanism -> Playbook

Best for transformation stories.

Structure:

```text
1. Before: old way
2. After: new way
3. Mechanism: why the new way works
4. Playbook: steps to copy
5. Case: example
6. Warning: common traps
7. Self-check: how to know if it applies
```

Use when the user asks for method upgrade, productivity improvement, or AI workflow transformation.

## Pattern 5: Myth -> Reality -> Rules

Best for correcting misconceptions.

Structure:

```text
1. Myth: what people believe
2. Reality: what actually happens
3. Why the myth persists
4. Rules: how to act correctly
5. Case: what it looks like
6. Test: how to check yourself
```

Use when the user asks for common mistakes, anti-patterns, or misconception correction.

## Pattern 6: Note -> Essay

Best for turning raw notes into an article.

Structure:

```text
1. Extract claims from notes
2. Select one core stance
3. Group evidence under the stance
4. Build outline
5. Draft around one reader problem
6. QA for stance, fact discipline, and Chinese AI tone
```

Use when the user provides Obsidian notes, meeting notes, research notes, or scattered bullet points.

## Selection Rule

If unsure:

- choose Pattern 1 for opinion essays
- choose Pattern 2 for method articles
- do not combine too many patterns in one article
