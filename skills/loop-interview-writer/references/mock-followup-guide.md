# Mock 追问模式库

> 按题型选择适用追问，不要求非故事答案提供数字或 Result。每次最多 3 个问题；修订与澄清分别遵守 SKILL.md 的累计预算。预算耗尽仅列缺口。未答出细节是待澄清，不是诚信或心理诊断。

## 五类追问模式

### M1 数字深挖
- L1「这个 X% 是怎么统计出来的？」→ L2「基线是什么时候的数据？」→ L3「排除了别的因素吗（大盘涨/换季）？」
- 核对点：数字来源、分母、时段和推算式。可允许查记录后补充；一时未说明只标待核，不判虚构。定性成果改问采用记录或可观察变化。

### M2 角色边界
- L1「这个项目团队几个人？」→ L2「里面你具体负责哪块？」→ L3「如果把你换掉，结果会差在哪？」
- 测试点：A 是否被夸大。答案措辞强度不得超过账本角色记录。

### M3 反事实
- L1「如果重来一次，你会改哪个决定？」→ L2「当时为什么没这么做？」
- 核对点：是否说明当时选择及限制。未答出改进点只表示这一轮未展示，允许思考或补材料，不能推断只背没想。

### M4 失败探底
- L1「这个失败最大的代价是什么？」→ L2「你负责哪些决定或动作，哪些由别人负责？」→ L3「若有后续变化，具体是什么、依据是什么？没有也可如实说明。」
- 核对点：具体失败、实际代价和有记录的变化；不强迫用户编造责任百分比或后续收益。

### M5 压力质疑
- L1「说实话，这个结果我觉得一般。」（不提问，只否定）
- 只观察本次能否补充事实语境与边界；不根据紧张、口音或停顿推断情绪稳定性、人格或诚信。可选低压问法：“请补充当时约束和判断标准。”

## 追问后的处理分流

| Mock 结果 | 动作 |
|---|---|
| 答案有洞但账本有料 | 生成具体修订规则 → 回 QA loop |
| 洞在数据缺失 | 进追问清单，答案标〔待补数据〕降级表述 |
| 角色边界未说明或材料矛盾 | 引用原句并澄清；只有材料支持时才降为“负责其中 X”，不从答不出反推真实角色 |
| 三层全接住 | 标记「追问预案」进故事卡 |
