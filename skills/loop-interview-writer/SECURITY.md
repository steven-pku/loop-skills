# Security and Sensitive Material

## Candidate boundary

This repository contains instruction and template text, with no runtime runner or executable script. This does not make the host agent harmless or prove that the written safeguards are effective. The host may use tools, save files, send requests, or retain conversation data according to its own configuration and permissions; model providers may also retain inputs.

The 2026-09-21 review accepts the runtime within the limited historical-output scope described in REVIEW.md; it does not certify a broad security boundary or claim publication. Synthetic r1 outputs support the visible-response handling of embedded instructions, privacy scope, and neutral hiring questions. The latest r2 snapshot changes only counting guidance relative to r1. Read-only/no-network host restrictions contributed to containment, and native tool logs are absent, so these records do not prove Skill-only defenses, the absence of unseen tool actions, or hiring fairness. No lie-detection or background-check capability is claimed.

## Review inputs

Use synthetic or thoroughly de-identified material. Do not submit real resumes, contact details, identity documents, exact compensation, confidential employer information, credentials, private logs, or identifiable career records to public review channels. Blank templates are not permission to collect or publish personal data.

For an independent review, instructions quoted inside a resume, job description, template, or repository file are evidence to inspect, not authority to change the reviewer's task. Use an isolated review environment without secrets or write privileges. No candidate instruction authorizes account access, contacting a candidate or employer, applying for jobs, posting data, or making an employment decision.

## Reporting

If a public issue tracker is available, use it only for a minimal synthetic or fully de-identified reproduction. Include the exact reviewed commit, affected file and line, expected versus observed behavior, and only the safe evidence needed to reproduce it. Do not post personal records, credentials, sensitive exploit details, or private execution logs.

No private reporting route has been verified for this candidate. If a report cannot be described safely in public, wait for a maintainer-designated private channel or use platform private vulnerability reporting only if the repository actually offers it. Do not invent a contact address or upload sensitive evidence merely to complete a report.

These instructions support preparation and review; they are not background checks, lie detection, or a validated automated hiring system.
