# Example — 抖音单条诊断产出（合成数据案例）

> 来源：公开脱敏合成示例；内部试运行记录不随公开候选分发。以下数字仅演示算术与输出结构，不是真实后台数据，不能让实际任务通过 Data Gate。
> 合成输入：播放 4200 / 完播 18% / 5s 完播 41%；合成账号近 10 条基线：播放 15000 / 完播 31% / 5s 完播 52%。内容：60s 知识口播，开头 8 秒自我介绍+预告。

## 诊断输出（节选）

**演示 Gate**：本页不能代表真实 Gate 通过。它只演示：若真实会话中的用户明确声明同结构数字抄录自后台并给出近 10 条基线，则这些数字可作为 B 类材料，核验状态写`用户转录，未独立核验`；本页来源始终是合成，允许演示算术或审查报告文字，不能做真实表现归因，也不能给真实归因范围的 Pass。若审查这段示例，可给“报告文字审查”的范围限定结论；节选不套整稿 /100。

**演示 Metric Check**：假设真实会话中的用户当前后台确有“完播率”和“5 秒播放率”字段；本项目未取得两者精确定义与通用阈值的一手来源，因此本页只演示账号内算术比较，字段口径标〔待核〕。实际任务仍须先通过真实数据 Gate。

**归因（按证据等级排列）**：

演示性数据观察

- [演示算术] 两个所报百分数为 41% 与 52%，数值差为 -11pp。字段定义、观测窗和分发阶段尚未对齐，不能据此判断留人表现高低。输入另明确给出：前 8 秒是自我介绍+预告
- [演示算术] 可列出 4200 与 15000、18% 与 31%、41% 与 52% 三组数；在可比性确认前，不把数值排序升级为表现排序，也不推断推荐机制或因果方向

合理猜想（待验证）

- [D] 中段具体流失点〔待验证〕（无留存曲线）
- [D] 发布时机影响未知〔待验证〕（未提供发布时间、观测窗与历史时段分布）

**改进规则（3 条，一次一变量）**：

1. 砍掉前 8 秒自介+预告，首句直接呈现内容问题；这是基于可见开头的工艺建议，不能据当前数字预测回到 52% → 脚本层
2. 15-20 秒处放第一个可带走结论；验证型规则：看完播率是否向自身基线回升，无变化仅记为本轮未支持中段假设 → 脚本层
3. 结尾换具体问题式评论钩；观察评论率变化 → 脚本层

## 看点

- 每条结论挂牌；平台字段定义未核时不借 A 级机制包装 B 级数据
- 缺少发布时间与观测窗时，「时机」保持未知，不用相邻指标代替缺失事实
- 规则 1 与 2 不同时改（一次一变量）；单条无变化只削弱支持，不宣告假设作废
