# Improvement Rules Standard — 改进规则可执行标准

诊断的出口不是「懂了」，是「下条内容改什么」。每条规则三件套：**具体动作 + 预期可观察效果 + 路由标签**。

## 合格判据

| 判据 | 合格 | 判负 |
|---|---|---|
| 可执行 | 「开头 3 句换冲突钩子，砍掉前 8 秒背景铺垫」 | 「提高内容质量」「优化开头」 |
| 可验证 | 「只测开头变量；以同口径账号基线为参照，观察 3 秒字段是否改善；不保证回到基线」 | 「效果会更好」 |
| 有路由 | 标注 选题层/脚本层/文章层/本层可修 | 无归属的泛泛建议 |

## 路由标签

- **选题层**（→ 选题决策步骤）：题材/角度本身没承载力——再好的钩子救不了没人关心的题。信号：非粉推荐量正常但全链路数据平庸。
- **脚本层**（→ 口播／视频脚本步骤）：口播钩子弱、视频叙事结构拖、口语化差。信号：口播或视频的开头／中段流失显著。
- **文章层**（→ 图文／长文写作步骤）：正文结构、段落顺序、图片序列、清单内容需要改。图文首图之后的图片顺序与正文改写都归这里。
- **本层可修**（包装层，不动正文）：标题／封面或首图／标签／发布时间／合集归属。信号：内容数据健康但曝光／点击异常。

路由的意义：复盘的产出直接变成下一次选题、脚本或图文创作的输入，不在本 skill 里空转。

## 回归验证钩子格式

每条 D 级假设和每条改进规则都带钩子：

```markdown
→ 回归钩子：下条〔改什么〕；看〔哪个指标〕是否〔怎样变化〕；若无变化则〔本轮未获支持，保持 D 或将下一个假设提到测试队列前列〕
```

- **一次一个变量**：用户下条内容同时改五处时，如实说明归因将再次不可分——建议排测试队列（批量模式自动生成）。
- **单次不作废**：一个可比内容没有出现预期变化，只能说明本轮未支持假设；除非命中确定性的事实反证，否则不能用单条结果宣告内容假设已被证伪。
- 钩子要写用户真会看的位置：输出末尾集中列出「下条内容检查清单」。

## 反模式

- **建议清单轰炸**：10 条泛泛建议不如 2 条带钩子的具体规则。上限：单条诊断 ≤5 条规则。
- **替用户定 KPI**：预期效果对比对象只能是账号自身基线，不发明「行业水平」。
- **把目标写成保证，或把预测误读成保证**：拟议目标、条件预测与观察结果分开写；“预期”保留原意，但预测幅度与条件仍须说明依据。无依据的“预期十倍”不能仅靠限定词过审。
- **把 C/D 级归因直接翻译成规则**：D 级假设的规则必须以验证为目的（「测一下」），不以整改为目的（「必须改」）。
