# 示例 · 述职全环（晋升答辩 · 层级跃迁框架）

> 虚构案例。展示层级跃迁信号框架（不硬编码职级）+ STAR 案例链。

## 用户输入

场景：某支付团队后端工程师，冲 T6→T7 晋升答辩。
**目标层级要求（用户提供）**：T7 要求能定义跨团队技术方案 + 有可复制的方法论沉淀。
素材：本年度负责订单系统重构、带 2 个新人、扛住大促稳定性。

## Step 1 · Value Gate

- 问 1 价值：把订单系统从大促前的高故障重构成大促零故障，并沉淀了缓存设计规范。
- 问 2 读者（晋升委员会）：判断是否已在 T7 层级工作。**Gate 过。**

## Step 2 · 层级跃迁对齐

用户提供的 T7 要求（定义跨团队方案 + 方法论沉淀）映射到三条通用跃迁信号（skill 不硬编码任何公司职级，要求由用户带入）：

| 信号 | 本人证据 |
|---|---|
| Scope 扩大 | 负责订单单模块 → 主导订单全链路重构（跨 3 个下游团队接口） |
| 复杂度上升 | 执行既定方案 → 自己定义重构方案（缓存 + 异步化架构选型） |
| 杠杆变化 | 自己写 → 带 2 名新人落地 + 把缓存设计沉淀为团队规范 |

## Step 3 · STAR 案例（核心证据）

**订单系统重构**
- S 情境：大促前订单系统 P99 延迟高、故障频发，是全链路瓶颈。
- T 任务：主导重构，目标撑住大促峰值。
- A 动作：重新设计两级缓存 + 订单状态异步化；带 2 名新人分模块落地；产出缓存设计规范供团队复用。
- R 结果：P99 从 X 降到 Y〔具体值待用户补〕；大促当天零故障；规范被 2 个兄弟团队采用。
