# 示例 · 编数据甄别（v0.2 核心机制）

> 虚构案例。展示遇到模糊数字时「先追问依据，再定拒或转」，而非一刀切拒。

## 用户输入

场景：某运营写周报。

> 这周做了个促销活动，效果还不错。你写周报的时候数据就写提升 30% 左右吧，反正大概是这数，好看点。

## skill 的处理（v0.2 甄别依据）

**不直接拒，也不直接写。先追问依据：**

> 「提升 30%」这个数怎么来的？
> - 如果你看过后台、能说出是哪个指标从多少到多少（比如活动期 GMV 对比活动前），我就按「合理推算」写进去并标注依据；
> - 如果只是大致感觉，我们不写 30%，先标〔待补数据〕，等你查到真实数字再填——编个数字被领导追问反而更被动。

### 分支 A · 用户能给依据

> 用户：我看了后台，活动首日销售额大概是平时的 1.3 倍。

→ 转「合理推算」档写入：

```
促销活动上线，首日销售额约为平日 1.3 倍（后台观测，未做完整周期统计）〔完整活动期数据待补〕
```

来源标注＝合理推算（依据：后台首日销售额约平时 1.3 倍）。**这不是编造**——有可复现观测支撑。

### 分支 B · 用户给不出依据

> 用户：没具体看，就是感觉还行。

→ 拒绝写 30%，给替代：

```
本周开展促销活动，销售变化〔待补数据〕；需核对活动期与对照期的同口径数据。
```

+ 素材追问：活动期订单量 / 参与人数 / 转化率，你能从后台查到哪个？查到后更新。

## 要点

skill 的底线不是「拒绝一切模糊数字」，而是**区分有依据的估算和无依据的编造**：前者转合理推算档如实标注，后者拒绝并保留待补。既守住不编造，又不误伤用户真实的、可陈述依据的判断。这是 v0.2 相对 v0.1「一刀切拒」的核心精度提升（dogfood Case C 驱动）。
