# 示例 · 周报快环（流水账 → 成果导向）

> 虚构案例。人物、公司、数据均为演示用。展示 Value Gate 拦截流水账 + 素材追问代替编造。

## 用户输入（原始流水账）

场景：某跨境电商 SaaS 公司产品经理，写给直属产品总监的周报。

```
本周工作：
1. 跟进商品详情页改版，和设计、前端开了几次会
2. 处理了一批用户反馈的 bug
3. 参加了部门季度规划会
4. 跟客户成功团队对接了新功能培训
5. 看了一些竞品，做了调研
6. 下周继续推进详情页改版
```

## Step 1 · Value Gate（快环单问）

**问：本周创造的可感知价值是什么？**

素材全是动作（跟进 / 处理 / 参加 / 对接 / 看），读不出价值。**Gate 不过 → fast iteration（素材追问），不直接写稿。**

## Step 2 · 素材追问（≤5 条，按对总监的重要性排序）

1. 详情页改版推进到哪个里程碑？改版要解决什么问题（跳出率？转化？）？
2. 处理的 bug 多少个？有没有线上重大问题？影响多少用户 / GMV？
3. 季度规划会你有产出吗（提了什么被采纳的），还是纯参会？
4. 新功能培训后，客户成功团队能独立支撑了吗？覆盖多少客户？
5. 竞品调研得出什么结论 / 决策了？

## 用户回答（第二轮）

1. 完成核心交互方案评审，砍掉 2 个低价值模块，进开发排期；目标是降详情页跳出率（当前 68%）。
2. 处理 12 个，其中 1 个是购物车金额计算错误的线上 P1，影响全部跨境订单约 2 小时，已修复。
3. 提议 Q3 重点从「功能广度」转向「转化漏斗优化」，总监认可，已纳入 Q3 OKR 讨论。
4. 培训 CS 8 人，之后一级问题他们自己能答。
5. 看了 3 家竞品，发现都有「实时库存 + 物流时效」模块我们缺，已加入改版 backlog。

## Step 3 · 账本（节选）

- A01 购物车 P1：修复金额计算错误 → 止损，影响全部跨境订单约 2 小时｜12 bug 中唯一 P1｜来源：用户提供
- A03 Q3 方向：提议转向转化漏斗 → 总监认可纳入 OKR｜来源：用户提供
- A02 详情页评审：砍 2 模块进开发 → 目标降跳出（当前 68%，改版后目标〔待补数据〕）｜来源：用户提供

## Step 4 · Gate 复核 + Draft（结论先行 · 企业档）

价值一句话＝拦下影响全部跨境订单的购物车 P1 + 推动 Q3 转向被采纳。读者（总监）＝判断改版进度、Q3 对齐、有无需拍板。**Gate 过。**

```
## 本周结论
拦下一个影响全部跨境订单的购物车金额计算 P1（约 2 小时，已止损）；详情页改版核心方案评审通过、进开发；规划会提议的 Q3 转向转化漏斗优化已获你认可。文末一个方向待你确认。

## 关键进展
1. 购物车 P1 止损：修复金额计算错误，影响全部跨境订单约 2 小时；本周 12 个 bug 中唯一线上 P1。
2. 详情页改版进开发：核心方案评审通过，砍 2 个低价值模块收敛范围；目标降当前 68% 的跳出率（改版后目标下周补）。
3. Q3 方向获认可：提议重点从功能广度转向转化漏斗优化，已纳入 Q3 OKR 讨论。
4. 竞品缺口入 backlog：3 家竞品详情页均有「实时库存 + 物流时效」，我方缺，已加入改版 backlog。

## 风险与求助
- CS 培训覆盖 8 人、一级问题可自答，减少的打断量下周量化。
- 待你拍板：详情页改版是否本期纳入「实时库存 + 物流时效」（影响排期），还是放下一迭代？

## 下周计划
- 详情页改版：产出改版后跳出率目标 + 启动开发联调
- 给出 CS 培训后一级问题拦截率
```

## Step 5 · QA Scorecard

真实性审计：成果均可定位账本；68% 用户提供；两处〔待补数据〕（改版目标、打断量）如实保留。**通过。**

| 维度 | 得分 |
|---|---:|
| 成果导向 | 23/25 |
| 数据支撑 | 17/20 |
| 读者对齐 | 14/15 |
| 结构 | 14/15 |
| 语言 | 13/15 |
| 风险与求助 | 9/10 |
| **合计** | **90/100 · Pass** |

**要点**：原始 6 条流水账里，真正有汇报价值的是被追问出来的 P1 止损和 Q3 方向提议——它们在原素材里根本没写。skill 的价值不是润色流水账，是问出流水账里缺的成果。

（注：这是编写的演示案例，没有计时实测。纯流水账需要素材追问，实际耗时取决于用户补充信息，不承诺固定出稿时间。）
