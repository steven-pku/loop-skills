# 验证与限制

本仓区分四件事：文件来源、单款资源完整性、宿主实际加载、任务输出是否符合规则。

九款已发行产品来自固定公开提交；六款实验性产品没有正式 Release。`catalog/runtime-files.json` 记录本轮导入的运行文件摘要。可用仓内工具重做文件与打包检查；不因已有公开发行或通过静态检查而宣称所有行为通过。

此前九款合仓候选完成过文件与升级演练，前一组候选做过有限的 Codex 场景；最终包双宿主验收未完成。那些结果不能自动移给本次改变了文档与打包边界的源码快照。实验性产品原有已知问题仍以各自 REVIEW 为准。

各产品的 REVIEW.md 保留已知问题和证据局限；文档和分发整理不改变运行指令，也不增加产品成熟度。

没有宣称的新能力包括：事实自动保证、统一跨宿主兼容、真实业务效果、检测器规避、代替用户授权或自动发布。

## 可复现的文件检查

在仓库根目录运行 `python3 tools/check.py`，核对产品名称、版本、运行文件摘要以及单款资源与链接。运行 `PYTHONDONTWRITEBYTECODE=1 python3 tools/package.py --output /tmp/loop-packages` 可构建十五款独立包及摘要清单；输出目录必须在仓库之外。相同源码生成相同 ZIP 字节。

这些检查只验证文件与包装，不调用模型，不证明任务输出质量。
