# 安装与升级

先选择一款，再保留完整资源目录。新分发已完成文件、摘要和恢复检查；当前宿主的自动发现、首次调用与输出行为仍未重新验证。

## 取得完整产品

[源码快照下载页](https://github.com/steven-pku/loop-skills/releases/tag/source-2026.10.22) 提供十五款独立 ZIP、`manifest.json` 和 `SHA256SUMS.txt`。

以 Article Writer 为例，下载 `loop-article-writer-0.3.0-p2.zip`，核对 SHA-256 后解压，得到 `loop-article-writer/`。`p2` 是分发修订，区别于运行版本 `0.3.0`；系列快照标签不表示十五款一起完成了功能验收。

## 只选择一款

从 `skills/` 选择已发行产品，或在理解已知问题后从 `labs/` 选择实验性产品。实验室不属于默认安装集合。某些安装工具可能递归发现多个目录，因此不能用目录位置代替显式选择。

每款目录至少带有 `SKILL.md` 和随附资源。不要只拷贝入口文件，不建立对其他 Skill 目录的运行依赖。

## 项目级布局与验证范围

- Codex 路线：目标项目的 `.agents/skills/<产品名>/`。
- Claude Code 路线：目标项目的 `.claude/skills/<产品名>/`。

以上目录布局已通过文件复制、摘要与恢复检查；当前宿主的实际加载尚未重新验证，不能视为新增兼容承诺。安装应在隔离项目中进行，目标目录必须不存在；已有安装先备份到宿主发现范围外。

开启新会话并显式调用产品；查看实际读取的入口与资源，再做最小输入检查。未运行宿主时记录“未测试”，不以目录存在替代加载证据。

## 从旧仓迁移

旧独立仓的 clone、安装与 Release 下载链接不再作为匿名入口。先下载新包并核对文件摘要，再停止依赖旧仓。既有安装不会自动改写来源；保留本地修改，按[迁移与恢复](migration.md)检查恢复旧包的步骤。

新分发使用独立的分发修订与文件摘要，不覆盖旧版资产。文件检查不等于模型宿主兼容性通过。

## 从源码构建

克隆本仓后，在根目录运行：

```sh
python3 tools/check.py
PYTHONDONTWRITEBYTECODE=1 python3 tools/package.py --output /tmp/loop-packages
```

构建只使用 Python 标准库，不调用模型。输出必须在仓库之外。相同源码生成相同 ZIP 字节；包外清单记录每款的版本、状态和摘要。
