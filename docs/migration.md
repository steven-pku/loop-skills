# 从独立仓迁移

Loop 的源码、下载和问题反馈集中到本仓。产品原名称保持不变，九款已有运行版本和六款实验性状态分别列在[目录](../README.md)。旧独立仓的匿名访问与旧 Release 下载不再作为可用入口。

## 保留本地工作

1. 记录当前安装的产品名、版本、来源及安装位置。
2. 将旧产品的完整目录与安装器来源记录备份到宿主发现范围之外，保留你改过的提示、资源和配置。
3. 下载目标产品的新独立包，核对摘要，先解压到一个新的普通目录。
4. 比较旧目录与新目录；本地改动逐项决定是否保留，不把整个新包直接覆盖旧目录。
5. 在隔离项目中试用。确认实际加载来源与结果后，再替换日常项目中的对应产品。

原名称相同不意味着第三方安装器会自动更新仓库来源。请使用安装器自身的来源管理功能；其具体迁移命令未在本次重新验证。不要同时保留两个可被发现的同名产品目录。

## 出现问题时恢复

退出使用该产品的会话，将新目录移出发现范围，再恢复完整旧目录及旧来源记录。重新打开会话并确认只发现一个同名产品。不要用重新下载旧公开链接作为唯一回滚方式；旧目录的本地备份应在迁移之前准备好。

本次检查了两种项目目录布局中十五款产品的复制、备份与恢复，逐文件摘要一致。检查范围是文件操作；没有据此宣称自动发现、模型行为或第三方安装器升级通过。

## 来源与身份

`catalog/products.json` 记录产品版本、来源仓库和固定提交；`catalog/runtime-files.json` 记录导入运行文件的摘要。来源名称与旧提交是历史标识，不保证旧链接可匿名访问。新源码以本仓固定提交为准，下载包另有分发修订和 SHA-256。

文档整理没有修复实验性产品的全部已知缺陷。每款的 `REVIEW.md` 与运行指令继续共同定义其适用范围。
