# 从旧仓迁移与回滚

产品的完整名称不变，但同名不意味着安装器自动改写来源锁。此轮只验证人工项目级目录替换；第三方安装器的来源记录更新未验证。

## 每款独立升级

1. 确认旧安装的固定版本、完整文件清单和用户修改；未知来源或修改不要静默覆盖。
2. 把整个旧目录及已知来源记录完整备份到宿主发现范围之外。备份不能放在 `.agents/skills` 或 `.claude/skills` 中。
3. 保留备份后，将旧安装移出发现范围，再安装完整新目录；不要把新包解压叠加到旧目录。
4. 核对只发现一个同名产品、运行文件摘要匹配、旧残留不参与运行。开启新会话验证实际使用。
5. 失败时移出新安装，完整恢复旧备份和原来源记录，再开新会话。其他八款不随单款故障回退。

此流程在两种项目目录中完成十八条旧包→新包→旧包的文件级演练。每路线另测本地修改和旧残留两个夹具，完整备份与恢复通过。它不代表模型行为、自动安装器或未知个人安装环境已通过。

## 旧链接与发行

旧仓保留原 commit、tag、Release 和资产，不重写或删除。固定对象清单见[旧链接清单](../distribution/legacy-links.json)。旧首页迁移横幅及浮动 latest 的实际行为，只有正式入口切换后才更新；旧安装命令在切换前仍取得旧源。

原索引 README 的六个主要中文标题保留，减少锚点变化。旧历史文档维持原文；历史内相对路径由其固定源链接解释，不改造原评测证据。

## 切换和归档门

每款先通过来源、包内闭合、两条宿主首次使用、同装边界、升级恢复与公开资产回读，再切换新仓入口。旧仓横幅更新后，至少经历一次独立新会话复验；确认无未处理的安装或回退阻塞并保存回执后，才逐款归档。当前未切换、未归档。

归档后原对象仍需可取得；[GitHub 官方归档说明](https://docs.github.com/en/repositories/archiving-a-github-repository/archiving-repositories)只证明只读与可解除归档机制，不替代兼容性验收。
