# 立项闸门与用人方评审

## 立项闸门评分

Phase 4 对三个候选各打一次分，每项 1–5 分：

| 项目 | 1 分 | 5 分 |
|---|---|---|
| JD 相关度 | 与 JD 职责无直接对应 | 直接命中职责第一条 |
| 任务真实性 | 岗位上不会有人做这件事 | 就是该岗位每周在做的事 |
| 资料可得性 | 需要内部数据才能开始 | 公开资料足够支撑全程 |
| 可展示证据 | 结束时只有一份文档 | 有截图、记录、编码表等多类可查看产物 |
| 用户可解释性 | 用户答不出为什么这么做 | 用户能解释每一步取舍 |
| 时间难度 | 7 天明显做不完 | 按用户可投入时间有富余 |
| 数据与合规风险 | 涉及内部或个人敏感数据 | 全程公开资料，无隐私风险 |

立项条件，全部满足才立项：

- 总分 ≥ 25（满分 35）；
- 资料可得性 ≥ 3；
- 时间难度 ≥ 3；
- 数据与合规风险 ≥ 4。

最高分候选仍不满足时，停止并建议换目标：换更小的问题、换资料更可得的产品、或换岗位方向。不得把明显做不完的项目排进 7 日计划。

## 用人方评审 Rubric

Phase 6 每轮按此评分：

| 维度 | 权重 | 低分锚点 | 高分锚点 |
|---|---:|---|---|
| JD 相关度 | 20 | 做的是通用分析，与该岗位职责对不上 | 每个结论都对应一条 JD 职责 |
| 岗位任务真实性 | 15 | 像课程作业，实际岗位不这么工作 | 就是该岗位会交给实习生的活 |
| 证据与来源 | 20 | 结论追不到来源，或来源写得无法复现 | 每个结论指向具体 E2／E3 证据 |
| 分析与决策质量 | 15 | 只有描述与罗列，没有取舍 | 有明确判断、依据和放弃的选项 |
| 原创与诚实披露 | 15 | 身份含糊、指标来路不明、AI 参与未说明 | 项目身份、假设、边界、AI 参与全部写明 |
| 面试可解释性 | 10 | 用户答不出「为什么这么判断」 | 用户能独立复述逻辑并回应追问 |
| 交付完成度 | 5 | 缺核心交付物 | 交付物齐全且可直接发送 |

## 退出门

同时满足才算通过：

- 总分 ≥ 80；
- Fatal = 0；
- 至少 3 项可查看产物；
- 关键结论有来源或被明确标为假设；
- 用户可独立解释核心判断；
- 项目身份未伪装任职。

数值分只用于诊断。Fatal 优先于总分：有 Fatal 时无论多少分都不通过。

## 专业外观 vs 真实证据

评审的第一动作是把这两者分开：

| 看起来专业 | 是否等于证据 | 检查方式 |
|---|---|---|
| 排版整齐、图表多 | 否 | 每张图背后有原始记录吗 |
| 术语密集 | 否 | 换成大白话还成立吗 |
| 框架完整（背景—分析—方案—展望） | 否 | 分析部分有自己的观察吗 |
| 结论有具体数字 | 否 | 数字来自哪，能复算吗 |
| 篇幅长 | 否 | 删掉复述 JD 的部分还剩多少 |
| 有截图、原始记录、编码表 | 是 | 别人能照着复现吗 |
| 有反证与边界说明 | 是 | 证伪方式写清楚了吗 |

作品集越漂亮，越要先查证据密度。

## 每轮 3 个最高价值修改

从当前问题里选 3 个，按下列顺序取：

1. 所有 Fatal；
2. 分数最低维度上的 Major；
3. 面试最可能被追问且当前答不上的点。

每个修改必须写清：改什么、为什么改、改完用什么证明改到位。不给「再优化一下表达」这类不可验收的建议。

## 有效进步

一轮算有效进步，必须至少做到一项：

- 新增证据：出现了上一轮没有的 E2 或 E3 产物；
- 降低风险：去掉了一个无来源结论，或收窄了结论范围；
- 澄清判断：把一个含糊表述改成有依据的取舍说明。

只换词、加图、扩写、调整排版不得提分。提分必须引用本轮新增的具体证据。

## Fatal

- 把个人项目写成在目标公司或任何公司任职；
- 虚构用户数、转化率、收入或实验结果；
- 抄袭他人作品集、案例或分析结论；
- 使用企业内部或泄露的数据；
- 选择 7 天内明显无法完成的过大项目；
- 完成招聘方禁止 AI 的真实考核并隐瞒；
- 用户不能解释核心判断却仍输出「完成」。

## 扣分证据

每次扣分必须引用：

- 对应 JD 条目或交付物名称；
- 当前文本或缺失项；
- 对应评分维度；
- 修复动作。

不得用「深度不够」「不够亮眼」等不可验收表述。
