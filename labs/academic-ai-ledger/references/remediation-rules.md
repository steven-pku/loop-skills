# 补救规则

## 可做

| 动作 | 适用情形 | 验收标准 |
|---|---|---|
| 补人工核验 | 采用内容未经核验 | 逐条核对来源与事实，写下核验方式与结论 |
| 恢复原始版本 | 改动无法解释来源 | 找回本人原稿版本，说明差异 |
| 删除未经核验内容 | 无法核验且不可或缺性存疑 | 删除后论文仍成立，或由本人重写 |
| 本人重做 | 采用内容触及核心判断 | 用户能独立解释方法、过程与结论 |
| 向导师说明 | 存在需确认或高风险事件 | 说明含事实、条款和拟采取动作 |
| 准确披露 | 条款要求披露或事实需要说明 | 披露与账本逐项一致 |
| 准备答辩解释 | 任何被采用的 AI 输出 | 用户能回答答辩压力测试七问 |

## 不可做

- 伪造时间或对话；
- 修改记录制造更早时间；
- 补写不存在的历史提示词或截图；
- 欺骗或规避 AIGC 检测；
- 隐瞒明确禁止的使用；
- 把未做的核验写成已做；
- 删除已披露事件以让账本看起来干净。

以上任何一项被请求时，说明边界并停止，同时给出真实路径。

## 降 AI 率请求的处理

用户要求“改得检测不出来”“降 AI 率”“改写到过检”时：

1. 说明这属于规避检测，本 Skill 不做；
2. 指出真实问题通常是采用内容缺少本人主体性，而不是文字特征；
3. 给两条路径：如实披露，以及由用户本人重做该部分内容；
4. 把该事件标为 `高风险待整改`，写入整改动作；
5. 提醒检测结果与合规判定由学校决定，本 Skill 不预测检测分数。

## 整改动作格式

```markdown
### 整改 R01
- 对应 Event：
- 风险：
- 判决：
- 动作：
- 由谁完成：
- 验收标准：
- 期限：
- 完成后证据：
- 当前状态：Open／In Progress／Done／Need Advisor Confirmation
```

状态改为 `Done` 必须附证据。没有证据的整改一律留在 `In Progress`。

## 时间顺序

补救只改未来，不改过去：

- 现在补做的核验，记为今天的新事件或整改记录；
- 不得把今天补的核验写成当初就做过；
- 已经提交过的版本不追溯修改，只在说明中写清后续处理。

## 停止条件

出现下列情形，停止推进并转导师或学校：

- 存在明确禁止的使用；
- 数据真实性受影响；
- 用户无法独立解释核心分析或结论；
- 整改需要撤回或重交已提交材料。
