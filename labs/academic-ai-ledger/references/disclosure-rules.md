# 披露规则

## 逐项回指

披露草案的每一条都必须回指账本中真实存在的 Event ID。

检查顺序：

1. 草案中出现的每个 Event ID 在账本中存在；
2. 账本中 `Disclosure Needed: Yes` 的每个 Event 都出现在草案里；
3. 草案描述的工具、环节、采用范围与账本字段一致；
4. 草案没有提到账本里不存在的使用。

任何一项不通过，先修账本或修草案，不得先交付。

## 披露状态

| 状态 | 使用条件 |
|---|---|
| `Disclosed as required` | 有适用条款要求披露，草案已按条款格式写出 |
| `No disclosure required by provided rule` | 用户提供的适用条款明确不要求披露 |
| `Need Confirmation` | 条款缺失、含义不清或适用对象不符 |
| `Prohibited use identified` | 存在落在明确禁止条款内的使用 |

只有用户提供的适用规则能支持第二种状态。规则未知时一律 `Need Confirmation`。

## 措辞规则

- 不得生成“本文未使用任何 AI 工具”等与账本不符的表述；
- 不得用“仅做少量润色”等无法核验的模糊量词掩盖实际采用范围；
- 不得把未核验内容写成已核验；
- 工具名与版本按账本原样写，未知就写未知；
- 用户本人完成与核验的部分要写清楚，便于答辩时对应。

## 披露句式

```markdown
本文在〔论文环节〕使用了〔工具与版本〕，用于〔目的〕。
输入为〔输入摘要〕，输出为〔输出摘要〕。
实际采用〔采用内容与位置〕，并由本人通过〔核验方式〕核对，最终修改为〔最终修改〕。
对应记录：〔Event ID〕。依据：〔条款位置〕。
```

学校有规定格式时，先用学校格式，再把本 Skill 的字段填进去。

## 无政策时

- 仍可生成事实性说明草案，标题写“AI 使用情况说明（待规则确认）”；
- 状态填 `Need Confirmation`；
- 草案末尾注明：本说明只陈述使用事实，不构成合规判断；
- 同时输出导师确认问题，请用户先取得正式规则。

## 附录材料清单

披露草案后附一张材料清单，列出可随论文提交或备查的材料：

| 材料 | 对应 Event | 形式 | 是否可提供 | 脱敏状态 |
|---|---|---|---|---|

不把不存在的材料写进清单。用户找不到的材料标 `无法提供`，并写明影响。
