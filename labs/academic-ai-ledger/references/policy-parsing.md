# 政策解析规则

## 必录字段

每份规则材料都要记录：

| 字段 | 说明 |
|---|---|
| 文件名 | 材料原名或用户描述的名称 |
| 发布单位 | 学校、学院、导师、期刊、竞赛主办方 |
| 版本或日期 | 发布日期、修订版本、生效学年 |
| 适用对象 | 本科、硕士、博士、某专业、某届、某课程 |
| 原文位置 | 章节号、条款号、页码或截图位置 |
| 来源等级 | `P0` 正式文件或导师原话；`P1` 权威专业规范；`P2` 二手资料或回忆 |

任何一项缺失都标 `Unknown`，不用推测填补。

## 五类分类

| 类别 | 判定条件 | 默认动作 |
|---|---|---|
| 明确允许 | 条款直接允许该类用途 | 记录条款，允许，按需披露 |
| 有条件允许 | 允许但附带披露、范围、比例或核验条件 | 记录条件，逐条核对是否满足 |
| 明确禁止 | 条款直接禁止该类用途 | 判 `规则明确禁止`，进 Fatal 检查 |
| 未说明 | 材料中找不到相关条款 | 标 `Policy Missing`，转确认 |
| 需导师确认 | 条款存在但含义、范围或适用对象不确定 | 生成确认问题，不自行裁决 |

“未说明”不等于“允许”。把沉默解释成许可是本 Skill 的典型错误。

## 适用对象判定

先确认三件事：

1. 用户的培养层次与专业是否落在该规则的适用范围；
2. 该规则覆盖的是毕业论文、课程作业还是期刊投稿；
3. 生效时间是否覆盖用户的写作时间段。

任何一项不匹配，规则不能直接套用，转 `Need Advisor Confirmation`，并在输出中写明不匹配的具体位置。

## 层级冲突

常见层级：学校 > 学院 > 导师 > 课程或期刊。实际优先顺序由学校规定，不由本 Skill 推定。

冲突处理：

- 保留全部冲突条款的原文与来源；
- 不自行宣布哪一条失效；
- 在给出确认问题前，按更严格的一条执行；
- 把冲突写进导师确认问题，标明两条各自会带来什么后果。

「按更严格的一条执行」**只适用于用户本人适用的多份冲突规则**。他校规则、网络通用政策等外部待核线索不参与从严执行，也不得被建议为临时执行标准——没有适用规则时状态就是 `Policy Missing`，事件级判决落 `Need Advisor Confirmation`。

导师口头允许与学校书面禁止冲突时，一律按禁止处理，并请用户取得书面确认。

## 版本与日期

- 规则有更新版本时，只用用户当前适用的版本；
- 用户提供的版本明显早于当前学年时，标 `规则可能已过期`，转确认；
- 无法确认版本时，不得把该规则当作合规依据；
- 记录用户查看规则的时间，便于日后追溯。

## 外部线索

网络上的通用政策、其他学校的规则、期刊的一般声明、模型记忆中的惯例，一律只作待核线索：

- 单独列在“待核线索”栏，不进入政策矩阵；
- 不用于生成任何允许或禁止判决；
- 提示用户去哪里取得正式材料。

## 输出格式

```markdown
### 政策 POL-01
- 文件名：
- 发布单位：
- 版本或日期：
- 适用对象：
- 原文位置：
- 来源等级：
- 原文摘录：
- 分类：明确允许／有条件允许／明确禁止／未说明／需导师确认
- 附带条件：
- 不确定点：
```
