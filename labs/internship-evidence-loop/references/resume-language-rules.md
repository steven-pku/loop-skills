# 简历与面试表达规则

## 唯一来源

简历 bullet、作品集条目、STAR 故事和 90 秒介绍只能从证据账本生成。

每条对外表述必须回指一个或多个 Event ID。账本里没有的事实，不得出现在对外材料里，即使用户口头说过。

用户提出新事实时，先回到 Weekly Loop 入账、标级、归因，再生成表达。

## 结构

```text
[角色强度词] + [具体动作] + [交付物] + [可证明的结果层] + [口径或边界]
```

四段中的结果层按 `outcome-rules.md` 取能证明的最高层，不取最想写的层。

## 动词强度对齐

简历动词强度不得高于账本 Attribution 字段的角色强度词。

| 账本角色 | 允许动词 | 禁止动词 |
|---|---|---|
| 独立完成 | 独立完成、搭建、产出 | 带领、统筹全局 |
| 主导 | 主导、设计、推动 | 带领团队、负责整条业务线 |
| 负责 | 负责、完成、交付、维护 | 主导、独立完成 |
| 参与 | 参与、支持、配合完成 | 负责、主导 |
| 协助 | 协助、辅助 | 参与核心、负责 |

## 数字规则

- 有基准、结果、口径三件套才写比例；
- 只有绝对量时写绝对量，并注明统计范围；
- 团队数字必须写清团队规模与本人部分；
- 脱敏后的数字用量级或区间，不用假的精确值；
- 任何数字都要能在面试中说出来源。

## 三种 bullet 模板

交付层：

```markdown
负责 <项目> 的 <模块>，独立产出 <交付物数量与形式>，交付物现存于 <可查看形式>。
```

采用层：

```markdown
负责 <工作>，产出的 <交付物> 被 <采用方> 用于 <用途>，沿用至 <时间>。
```

结果层：

```markdown
负责 <工作>，<指标> 由 <基准值> 变为 <结果值>（口径：<来源与时间范围>；该变化同时受 <其他因素> 影响）。
```

## 禁止表述

- 无基准的「提升 X%」；
- 「大幅」「显著」「高度认可」等无法核验的程度词；
- 把实习期项目写成任职经历，或省略实习字样造成误解；
- 把课程作业、个人项目写成公司项目；
- 把团队成果写成个人成果；
- 引用无法出示的奖项、评价或数据。

## 面试可解释性检查

每条对外表述必须能当场答出三个追问：

1. 你具体做了什么？（动作与时间）
2. 有什么可以看的？（证据与形式）
3. 哪些不是你做的？（边界与协作方）

答不出任意一问，就降层、降强度或删除该条。

结项运行时对最强 3 个案例各做一轮模拟追问，把用户答不上来的部分写回补证动作。

## 一致性

最终简历与证据账本不一致属于 Fatal。定稿前逐条比对：

- [ ] 每条 bullet 都有 Event ID；
- [ ] 动词强度不超过账本角色；
- [ ] 数字与口径与账本一致；
- [ ] 脱敏处理一致；
- [ ] 账本更新后，对外材料同步更新。
