# 证据等级与证据类型

## 等级

| 等级 | 定义 | 默认处理 |
|---|---|---|
| E0 | 无证据，只有愿望或模糊描述 | 不得形成肯定结论，只能进「无证据」清单 |
| E1 | 用户自述 | 可作为线索，必须标注「本人陈述」 |
| E2 | 可查看的产物、文件、截图或版本记录 | 可支持过程与交付判断 |
| E3 | 产物加可核验结果、第三方反馈或前后对比 | 可支持影响类结论 |

一条事件的不同字段可以不同级。常见组合是 Action 为 E2、Outcome 为 E1。账本按字段标级，不按整条事件取最高级。

## 实习场景常见证据类型

| 类型 | 举例 | 通常等级 |
|---|---|---|
| 自述 | 「我负责这块」「大概提升了不少」 | E1 |
| 产物 | 自己写的文档、表格、脚本、稿件、设计稿 | E2 |
| 过程记录 | 版本历史、任务卡、提交记录、排期表 | E2 |
| 数据 | 有口径与时间范围的前后数值 | E2 或 E3 |
| 反馈 | 上级或同事的书面评价原话 | E2 或 E3 |
| 采用证明 | 方案被写进正式文档、被排期、被上线 | E3 |
| 第三方确认 | 客户回执、跨部门确认、公开发布记录 | E3 |

## 升级规则

从 E1 升到 E2 只有一条路径：出现可查看的产物或记录。

从 E2 升到 E3 需要下列之一：

- 有口径的前后对比数值；
- 明确的采用记录；
- 第三方书面确认。

自信的措辞、更长的描述、更具体的形容词都不构成升级。等级只能因为新增可核验材料而变化，并在账本里写明变化来源。

## 不可升级的情形

- 用户回忆的数字，没有出处或口径；
- 团队看板里的总体数据，无法切出个人贡献；
- 上级的口头夸奖，无法复述原话也无书面记录；
- 已删除、无法再取得且没有留存副本的材料。

以上一律停在 E1，并在「弱证据」清单里写明缺口。

## 三张清单

每次周度运行输出：

- **强证据**：E2 及以上，且贡献边界清楚；
- **弱证据**：E1，或等级够但归因不清；
- **无证据**：E0，或用户希望写进简历却拿不出任何材料。

每条弱证据与无证据必须写明缺什么：缺产物、缺基准、缺第三方确认，还是缺贡献边界。

## 没有数据时的替代证据

当用户拿不到业务数据时，不编造数字。可改用：

- 过程证据：自己做的流程图、检查表、复盘文档；
- 规模证据：处理的条数、覆盖的人数、维护的表数量，只写自己能核对的口径；
- 质量证据：返工次数下降、被指出的问题类型减少，附具体例子；
- 采用证据：自己的模板或方法被同事继续使用；
- 反馈证据：请上级用一两句话书面确认承担的范围。

替代证据仍要标级，通常是 E2。它替代的是「数字」，不是「可核验性」。

## 与账本的关系

Evidence Level 字段记录当前等级，Next Evidence Action 字段记录把等级提高一档所需的最小动作。两者必须成对更新，不能只改等级不改动作。
