# 导师反馈分类与原子化

## 分类

| 类别 | 常见信号 | 需要确认的证据 | 常见误判 |
|---|---|---|---|
| 研究问题 | 太大、不聚焦、问题不成立、对象不清 | 当前研究问题、对象、范围、预期回答 | 把标题修改当作问题收窄 |
| 理论与概念 | 理论太散、概念不清、框架不够 | 概念定义、理论关系、研究问题映射 | 只增加理论名称 |
| 文献与证据 | 文献不足、综述像堆砌、缺证据 | 引用、来源、文献与主张关系 | 通过增加引用数量冒充改进 |
| 方法与数据 | 方法再想想、样本不合适、变量有问题 | 方法、样本、测量、数据来源、限制 | 用语言润色掩盖方法不匹配 |
| 结果与解释 | 解释过度、讨论不够、结论跳跃 | 原始结果、分析步骤、可支持范围 | 新增没有数据支持的结论 |
| 结构与表达 | 逻辑不清、重复、顺序有问题 | 段落功能、论证链、章节关系 | 把“逻辑”默认理解为句子不顺 |
| 格式与流程 | 格式不对、引用规范、提交要求 | 正式模板、截止时间、提交清单 | 把非正式偏好写成学校要求 |

## 原子化规则

把一条反馈拆成多个任务，前提是每个任务都能拥有独立的：

- 修改位置；
- 修改动作；
- 验收标准；
- 状态。

不要拆分：

- 同一问题的同义重复；
- 仅用于解释前一项的例子；
- 无法独立验收的碎片。

## 原子项格式

```markdown
### F01
- 导师原话：
- 来源／日期／位置：
- 类别：
- 明确要求：
- 可能含义：
- 当前证据：
- 未知：
- 是否需导师确认：
```

## 质量检查

- 原始反馈的每个独立要求至少出现一次；
- 原子项不得超出原话和上下文；
- 同一原话拆出多项时保留相同来源引用；
- 来源不明时不使用“导师要求”作为肯定表述。
