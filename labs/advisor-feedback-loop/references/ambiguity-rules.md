# 歧义、冲突与确认规则

## 四种表达

### 明确要求

原话和上下文只有一个合理、可执行解释。

格式：

```markdown
明确要求：……
证据：导师原话“……”。
```

### 可能含义

上下文支持一种解释，但导师没有明说。

格式：

```markdown
可能含义〔待确认〕：……
依据：……
替代解释：……
```

### 未知

缺少材料，无法支持解释。

格式：

```markdown
Unknown：缺少……
影响：无法判断……
补充方式：……
```

### 需导师确认

不同解释会改变研究问题、方法、数据、结论、提交资格或大量返工。

## 必须确认的情况

- 两次导师反馈方向冲突；
- 导师意见与正式规则冲突；
- “理论不够”“方法再想想”等模糊反馈可能导致不同路径；
- 需要改变研究问题、样本或方法；
- 用户只能提供转述，无法确认原话；
- 关闭标准只能由导师决定。

## 导师确认问题

最多输出 3 个，按影响排序。好问题必须：

- 引用具体原话；
- 给出两个或三个真实选项；
- 说明不同选择会影响什么；
- 避免把模型偏好塞进问题。

示例：

```markdown
您提到“研究问题还不够集中”。我理解有两种可能：
A. 保留研究对象，减少变量；
B. 保留变量，缩小研究对象。
您更希望我沿哪一方向调整？这会影响后续问卷与方法部分。
```

## 冲突处理

保留时间线：

| ID | 日期 | 原话 | 影响 | 当前状态 |
|---|---|---|---|---|

不要自行声明较早反馈失效。只在导师明确覆盖或用户提供正式新规则时更新。
