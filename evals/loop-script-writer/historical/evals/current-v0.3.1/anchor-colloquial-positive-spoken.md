# anchor-colloquial-positive-spoken

Anchor pair B（正例）。配对：`anchor-colloquial-negative-written`。

## Input

```text
用 loop-script-writer 的 QA Only 模式诊断这条 60 秒(标准 260 字/分)口播稿:
「AI 写脚本,快是真快。但你发现没——写出来全一个味儿。
我上个月测了 4 款工具,同一个选题,出来的开头能一模一样。
(停半拍)问题不在工具,在你喂给它的东西。
你只给选题,它就给你平均值。你给它你自己的案例、你的口头禅、你踩过的坑,
它才能写出像你的稿子。
我把测试记录整理成了一页对照表,评论区扣『对照表』发你。」
```

## Expected behavior

- 区分自然口语与实际超长呼吸行：认可停顿和自然表达；若两处长句有依据，可给 12–17 档，不强制高档
- 读稿模拟:126 字 vs 标准 60s 260 字，偏差 −51.54% —— **fatal「±30%」触发**（正例不等于全绿——本 case 故意埋了时长坑，测「口语好」与「时长达标」不混淆）
- Hook 类型可命名（冲突/痛点）;CTA 具体（扣关键词）
- 综合 verdict:Revise（因时长 fatal）,但语言评价独立依据实际表达，不能因时长 fatal 说成书面语频繁

## Pass criteria

- 按 /20 的实际语言锚点评分，不要求不可能的 25 分差
- 时长 fatal 不因整体印象好被放过——两维独立判定是本 case 的全部意义
