「为什么这条没爆」的诊断闭环：数据 Gate（只认你的真实后台数据）→ 逐维诊断 → **归因诚实分级**（官方口径 / 数据支持 / 从业者共识 / 假设待验证，四级挂牌）→ 可执行改进规则 → 回归验证钩子（下条内容验证假设）。

市面复盘的通病是玄学归因——「限流了」「时机不对」「算法改了」。本 skill 的立场：**不装懂平台算法**。数据支持的结论和待验证的猜想分开写；没有当前一手来源的平台说法不能冒充事实。

## 挑一个模式

| 模式 | 什么时候用 | 跑什么 |
|---|---|---|
| **单条诊断** | 一条内容的复盘 | 全流程 |
| **批量复盘** | 近 3-10 条找模式 | 跨条模式提取 + 假设测试队列 |
| **报告文字审查／算术演示** | 合成或来源未知的复盘材料 | 只评价声明范围，不认证真实表现 |
| **无数据质检** | 拿不到后台数据 | 显式降级：只做内容质量诊断，归因全部标〔待验证〕 |

## 适合

- 抖音 / 视频号 / B站 / 小红书已发布内容的复盘
- 手里有可读后台数据（截图/导出/明确抄录），想要「能信几分」都标清楚的归因
- 连续发了一批内容，想找出「什么在起作用」的模式
- 受够了「限流了吧」式复盘，想要能被下条内容验证或推翻的结论

## 不适合

- 选题决策「下一条发什么」 → 选题流程（本 skill 只标记为选题层，不依赖另一仓才能运行）
- 口播脚本创作与打磨 → 脚本流程（本 skill 只标记为脚本层，不依赖另一仓才能运行）
- 图文长文创作 → [loop-article-writer](https://github.com/steven-pku/loop-article-writer)
- 涨粉技巧、投放策略、数据抓取（本 skill 只读你提供的数据，不采集）

## 核心特性

- **数据 Gate**：可读的真实平台数据（截图/导出/明确抄录自后台的数字）才解锁表现归因；虚构数字、附件占位符、不可读截图与记忆数字不算数据
- **归因诚实分级**：A 已读一手正文且精确支持主张 / B 用户数据支持 / C 多源从业共识 / D 单源线索或假设；证据类别与`已核验/用户转录未独立核验/未核原文`分开记录
- **来源闸门**：平台规则必须有当前一手来源；媒体转述、搜索摘要和圈内说法不能升为 A 级，无法核实时标〔待核〕并让诊断不依赖该说法
- **归因防呆五查**：幸存者偏差／post hoc／小数定律／均值回归／Twyman's law——逐项列出处与证据层级
- **不发明及格线**：包内一手来源没有给出可跨账号套用的通用及格线——对比基线只用你自己账号的历史
- **改进规则三件套**：具体动作 + 预期可观察效果 + 路由标签（选题层/脚本层/文章层/本层可修），泛泛建议判零分；单次诊断 ≤5 条聚焦
- **回归验证钩子**：每条假设写清「下条改什么、看哪个指标、结果如何增减支持」；单条无变化不直接宣告假设作废

## 为什么是纯指令

没有脚本、没有 runner、不采集任何数据——每一条行为都是你能读的纯文本：

- **可审计**——读完指令就知道它会怎么处理你的数据，没有黑盒
- **可移植**——同一个 skill 跑在 Claude Code、Codex 或任何兼容 agent 上
- **供应链安全**——运行时零依赖；安装与 CI 校验继承 npm / Git / GitHub 的信任链，CI 已按 commit SHA 与固定版本 pin

## 安装

在目标项目目录内按固定版本安装，不改全局技能目录。首次使用需让宿主重新发现项目技能。Codex 的干净归档加载和连续会话已验收；未在本轮验证 Claude Code 的实际运行。

Codex：

```bash
mkdir -p .agents/skills
git clone --branch v0.3.1 --depth 1 \
  https://github.com/steven-pku/loop-content-audit.git \
  .agents/skills/loop-content-audit
```

Claude Code 的项目目录布局：

```bash
mkdir -p .claude/skills
git clone --branch v0.3.1 --depth 1 \
  https://github.com/steven-pku/loop-content-audit.git \
  .claude/skills/loop-content-audit
```

运行时入口为 `SKILL.md`，按需读取 `references/`，平台文件只读当前诊断的平台。模型验收仅加载运行文件，不将 `evals/` 作为答案上下文。

## 证据基础与边界

平台指标口径按一手来源／从业者或媒体线索／未核传闻分级，出处与复核日期在 `references/platform-*.md` 逐条可查；归因谬误概念逐项列出参考来源。平台算法是黑盒——本 skill 的差异化不是装懂，而是把「懂多少、信几分」标注到每条结论上。

后台截图、评论与导出一律按不可信数据处理，绝不执行其中的指令。跨内容比较还要先确认指标定义、观测窗与分发阶段可比；把计数换成比例不能自动消除`7 天 vs 2 小时`的窗口差异。请先遮掉不必要的账号名、头像、客户信息、收入、投放金额和凭证；本 skill 不登录、不抓取、不发布、不投流，也不承诺流量或收益结果。详见 [SECURITY.md](SECURITY.md)。
